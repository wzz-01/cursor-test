## 2. 日期规则（最容易错，必须先懂）

### 2.1 业务日 vs 取数日

本表 `date_id` **不是自然日流水**，业务日期被归到**当月 1 号快照**。

因此：

| 概念 | 含义 | 示例 |
|------|------|------|
| 业务日 `D_biz` | 报告落款「截至日」；通常是“昨天完整业务日” | 2026-07-18（假设 7/19 更新 7/18 数据） |
| 取数快照日 `D0` | `D_biz` 所在月的 1 号 | 2026-07-01 |
| 同比快照日 `D0_ly` | 去年同月 1 号 | 2025-07-01 |

**PDF/正文写「截至7月18日」，取数用 7月1日快照。禁止把落款写成 7月1日。**

### 2.2 财年

- 财年 = **当年 7/1 ~ 次年 6/30**
- 例：2025-07-01 ~ 2026-06-30 = **2025 财年**
- 例：2026-07-01 ~ 2027-06-30 = **2026 财年**
- 所有“年累计 / 年度目标”按财年，**禁止按自然年 1–12 月**

### 2.3 三段时间窗（必须分开，禁止混用）

以 `D_biz=2026-07-18` 为例：

| 段落 | 时间窗 | 取数日期 |
|------|--------|----------|
| ① 区域销售进度 | 仅业务日所在月 | `D0` vs `D0_ly` → 2026-07-01 vs 2025-07-01 |
| ② 业绩预警 | 近 3 个快照月 | 2026-05-01、2026-06-01、2026-07-01 |
| ③ 年度目标 | 本财年起始 ~ 当前月快照 | 本期：2026-07-01~2026-07-01；去年同期：2025-07-01~2025-07-01 |

说明：当 `D_biz` 落在财年首月时，③ 的年累计会接近当月快照，**这是正确现象**。

## 3. 计算公式

### 通用

- 金额展示：**原值 / 10000 → 万元**
- 达成率 = `SUM(amt_yesterday) / SUM(ys_products)`
- **预算不去重**（直接 SUM，不要 MAX/row grain 折预算）
- 同比增额 = 本期 - 去年同期
- 同比增速/增长率 = 增额 / 去年同期（除零 → NULL/算不出）

### ① 区域销售进度（当月）

在省区 + `D0` 上计算：

- 销售额、同比增额、达成率、增长率
- 省区达成率排名、增长率排名（在全部 `province_region_name` 中）
- 经销达成/增长、直营达成/增长
- 预估本月达成：优先评估 `amt_yg`；不合理则标「待补」
- 大单品达成率：无明确规则则括号留空
- Top3 / Bottom3：该省区 `sales_group_name` 按达成率

### ② 业绩预警（近3月）

- 连续三月下滑：城市 / 销售组 / 客户，严格 `M1 > M2 > M3`（各月 `SUM(amt_yesterday)`）
- 近三月达成率全国后 20% 销售组：全国销售组先算近3月达成率，取后 20%，再筛本省区
- 近3月达成率 = 近3月 `SUM(amt_yesterday)` / 近3月 `SUM(ys_products)`（预算仍不去重）

### ③ 年度目标（财年至今）

- 年累计销额 = 本财年起始日 ~ `D0` 的 `SUM(amt_yesterday)`
- 去年同期年累计 = 上财年对应区间 `SUM(amt_yesterday)`
- 增额 / 同比增速：基于上述两个年累计（方案1）
- **累计进度分母** = 同一财年累计区间内 **全部** `SUM(ys_products)`（不去重）
- 同期实际进度 = 去年同期年累计 / 去年同期区间 `SUM(ys_products)`；去年预算为 0 则写算不出
- 在全部省区单位中：进度排名、增速排名
