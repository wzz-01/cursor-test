# 能力地图与使用说明

## 一句话目标

你最终要具备的不是“看过很多 AI 新闻”，而是能够：

1. 判断一项 LLM/Agent 新技术是否重要；
2. 快速读懂论文和技术博客；
3. 设计并实现一个可靠的 LLM Agent 系统；
4. 在面试中清楚解释原理、架构、指标、风险和项目经验。

## 能力地图

### 1. 基础层：理解 LLM 本身

必须掌握：

- Transformer 的核心结构：Attention、FFN、LayerNorm、残差连接。
- 预训练与后训练：Pretraining、SFT、RLHF、DPO、RLAIF、RLVR。
- 推理能力：CoT、self-consistency、test-time scaling、reasoning model。
- 上下文窗口：长上下文不等于长期记忆，token 成本和噪声会影响 Agent。
- 幻觉与不确定性：为什么模型会编造，如何通过检索、工具和验证降低风险。

面试表达目标：

- 能用 2 分钟解释 Transformer；
- 能用 3 分钟解释为什么大模型需要 RAG；
- 能用 5 分钟讲清楚 SFT、RLHF、DPO 的区别。

### 2. RAG 与上下文工程层

必须掌握：

- 文档解析：PDF/网页/表格/代码仓库怎么转成可检索文本。
- 切分策略：固定长度、标题层级、语义切分、代码切分。
- 检索策略：向量检索、BM25、Hybrid Search、Rerank、多路召回。
- 生成控制：引用来源、拒答、答案校验、结构化输出。
- 评估：召回率、命中率、Faithfulness、Answer Relevance、端到端任务成功率。

面试表达目标：

- 能解释为什么“向量库 + prompt”不等于完整 RAG；
- 能设计一个企业知识库问答系统；
- 能讲清楚 RAG 失败的常见原因和排查流程。

### 3. Agent 架构层

必须掌握：

- ReAct：Reasoning 与 Acting 交替。
- Plan-and-Execute：先规划，再分步执行。
- Tool Calling：工具描述、参数 schema、调用约束、错误恢复。
- 状态管理：agent state、messages、scratchpad、memory、tool result。
- 控制循环：observe -> think/plan -> act -> observe -> finish。

面试表达目标：

- 能画出一个 Agent 主循环；
- 能解释 Agent 和 Chatbot 的区别；
- 能说明为什么工具调用必须有白名单、参数校验和超时控制。

### 4. 记忆与长期任务层

必须掌握：

- 短期记忆：当前对话、任务状态、临时变量。
- 长期记忆：用户偏好、历史事实、经验、工具使用模式。
- 记忆写入：抽取、去重、冲突检测、重要性评分。
- 记忆读取：相关性、时间性、可靠性、权限。
- 记忆更新：过期、遗忘、合并、纠错。

面试表达目标：

- 能解释“长上下文”和“长期记忆”的区别；
- 能设计一个多轮个人助手的记忆系统；
- 能说明记忆污染、隐私泄露和错误记忆如何治理。

### 5. 规划、反思与搜索层

必须掌握：

- 任务分解：递归拆解、里程碑、依赖关系。
- 搜索：Tree-of-Thought、LATS、beam search、MCTS 风格探索。
- 反思：从失败轨迹中总结经验，但不能盲信自我批评。
- 预算控制：最大步数、最大工具调用次数、成本上限、早停。
- 验证：单元测试、断言、外部工具、人工确认。

面试表达目标：

- 能说明什么时候需要规划，什么时候简单 ReAct 就够；
- 能解释反思机制的收益和局限；
- 能设计一个能自动修复代码的 Agent 流程。

### 6. 多智能体协作层

必须掌握：

- 角色分工：Planner、Executor、Critic、Retriever、Coder、Reviewer。
- 通信协议：消息格式、共享上下文、冲突合并。
- 协作拓扑：串行、并行、投票、树状、黑板系统。
- 失败模式：回音室、无效争论、成本爆炸、责任不清。
- 评估：任务成功率、协作轮次、冗余调用、最终答案质量。

面试表达目标：

- 能说明多 Agent 不一定比单 Agent 好；
- 能设计一个“代码生成 + Review + 测试”的多 Agent 系统；
- 能解释如何降低多 Agent 的 token 成本。

### 7. 工程生产层

必须掌握：

- 框架：LangGraph、AutoGen、CrewAI、LlamaIndex、MCP。
- 可观测性：trajectory trace、tool logs、token/cost、latency、failure reason。
- 安全：prompt injection、tool abuse、data exfiltration、权限隔离。
- 评估：离线 benchmark、在线 A/B、LLM-as-judge、人类验收。
- 部署：队列、超时、重试、缓存、降级、审计。

面试表达目标：

- 能从零设计生产级 Agent 架构；
- 能列出上线前必须做的评估；
- 能讲清楚如何定位 Agent “偶发失败”。

## 每天 1 小时的固定节奏

### 前 10 分钟：信息源扫描

只做三件事：

1. 看 1 个信息源；
2. 记录 1 条值得跟踪的新进展；
3. 判断它属于哪一层能力：模型、RAG、Agent、记忆、多 Agent、评估、安全、产品。

### 中间 35 分钟：主任务

按 12 个月计划执行。主任务只选一个，不要同时打开太多资料。

常见主任务：

- 精读论文一个小节；
- 复现一个 Agent loop；
- 写一个工具调用 demo；
- 做 3 道面试题；
- 改进一个项目指标。

### 最后 15 分钟：复盘输出

写下：

- 今天学到了什么；
- 哪个概念能解释给别人听；
- 哪个问题还没懂；
- 明天继续做什么。

## 每周产出要求

每周至少保留以下产出：

1. 一页学习笔记；
2. 一个可运行小实验，哪怕只有几十行代码；
3. 三道面试题的口头答案；
4. 一条“本周最重要的新进展”；
5. 一个下周要验证的问题。

## 判断一篇论文是否值得精读

优先级从高到低：

1. 是否提出了新的 Agent 控制范式；
2. 是否解决了生产痛点：成本、延迟、可靠性、记忆、安全；
3. 是否有可复现代码和 benchmark；
4. 是否被多个后续工作引用或工程框架采用；
5. 是否能转化为你自己的项目能力或面试表达。

## 不建议的学习方式

- 只收藏链接，不写自己的解释；
- 一天同时看 5 篇论文；
- 只看中文二手解读，不读原文摘要和实验表格；
- 只跑框架 demo，不理解 state、tool、memory、eval；
- 只追模型榜单，不看 Agent 工程失败案例。

## 最终作品集目标

12 个月结束时，建议形成 4 个可展示作品：

1. **个人知识库 RAG**：支持引用、重排、评估。
2. **工具调用 Agent**：能调用搜索、计算、文件、数据库等工具。
3. **长期记忆 Agent**：能跨会话保存偏好、更新事实、处理冲突。
4. **软件工程 Agent**：能读取 issue、修改代码、运行测试、生成报告。

每个作品都要有：

- 架构图；
- README；
- 运行方式；
- 关键代码说明；
- 评估指标；
- 失败案例和改进方向。
