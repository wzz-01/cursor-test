# 核心论文中文精读与中英对照

> 说明：本文件不是逐字全文翻译，而是“中文精读 + 英文术语对照 + 面试表达 + 复现建议”。这样更适合快速理解论文、建立工程能力和准备面试。

## 通用读论文框架

每篇论文都按下面 7 个问题理解：

1. **Problem**：它解决什么问题？
2. **Motivation**：为什么已有方法不够？
3. **Method**：核心方法是什么？
4. **Architecture**：系统由哪些模块组成？
5. **Experiment**：用什么任务和指标证明有效？
6. **Limitation**：有什么局限？
7. **Engineering**：如果我要落地，需要测试什么？

# 01 ReAct: Synergizing Reasoning and Acting in Language Models

英文原版：`../papers_en/01_ReAct_Synergizing_Reasoning_and_Acting.pdf`

原始链接：https://arxiv.org/abs/2210.03629

## 中文精读

ReAct 是 LLM Agent 领域的起点级论文。它的核心观点是：大模型不应该只在内部“想”，也不应该只机械地“调用工具”，而应该把推理和行动交替起来。模型先产生一个 Thought，决定下一步 Action，环境返回 Observation，然后模型继续基于新观察推理。

这解决了纯 Chain-of-Thought 的一个问题：模型只能在自己的参数和上下文里推理，遇到外部知识或环境变化时容易编造。ReAct 通过行动获取外部信息，让推理过程被环境反馈修正。

## 中英术语对照

- Reasoning：推理
- Acting：行动
- Thought：中间思考
- Action：工具调用或环境动作
- Observation：工具/环境返回结果
- Trajectory：完整执行轨迹

## 核心要点

1. ReAct 把 reasoning trace 和 action trace 合并。
2. 每一步行动后都获得 observation，减少闭门造车式幻觉。
3. 它不是完整框架，而是一种 Agent 控制范式。
4. 后续 LangChain、LangGraph、AutoGen、工具调用 Agent 都能看到 ReAct 的影子。

## 局限

- 依赖 prompt 和模型遵循格式的能力；
- 容易循环或执行无效动作；
- 对工具安全、权限、成本没有完整治理；
- Thought 可能包含不可验证推理，生产系统不应盲信。

## 最快复现实验

做一个最小 Agent：

1. 工具 1：calculator；
2. 工具 2：search_mock，从本地字典返回信息；
3. 工具 3：finish；
4. prompt 要求输出 `Thought/Action/Action Input`；
5. 记录每一步 trajectory。

测试：

- 简单数学题；
- 需要查资料的问题；
- 工具返回错误的问题；
- 超过最大步数的问题。

## 面试表达

ReAct 的核心是把语言模型的推理过程和外部行动过程交替组织起来。相比只用 CoT，它可以通过工具或环境获取新信息；相比只做工具调用，它保留了中间推理和任务分解能力。工程落地时，我会给它加最大步数、工具白名单、参数校验和完整 trace。

# 02 Toolformer: Language Models Can Teach Themselves to Use Tools

英文原版：`../papers_en/02_Toolformer_Language_Models_Can_Teach_Themselves_to_Use_Tools.pdf`

原始链接：https://arxiv.org/abs/2302.04761

## 中文精读

Toolformer 关注的问题是：模型如何学会在合适的时候调用工具。它不是简单写 prompt，而是构造训练数据，让语言模型看到“什么时候插入 API 调用会提高预测效果”。如果调用工具后的结果能让模型更好预测后续文本，就把这个调用样本保留下来。

这篇论文的重要性在于，它把工具使用从纯 prompt 技巧推进到训练范式：模型可以通过自监督数据学会工具调用。

## 中英术语对照

- API Call：接口调用
- Self-supervised Learning：自监督学习
- Tool Use：工具使用
- Augmented Language Model：增强语言模型
- Filtering：样本过滤

## 核心要点

1. 工具调用可以被构造成语言建模训练样本。
2. 关键不是让模型总是调用工具，而是学会何时调用。
3. 工具包括计算器、搜索、翻译、日历等。
4. 工具结果要真正提升模型预测质量，样本才保留。

## 局限

- 需要训练或微调，不如 prompt Agent 容易复现；
- 工具集合相对固定；
- 对复杂多步任务支持有限；
- 训练数据过滤策略会影响最终工具偏好。

## 最快复现实验

不必完整训练 Toolformer，可以做一个简化实验：

1. 准备 30 条问题，其中一部分需要计算器；
2. 对比“直接回答”和“调用计算器后回答”；
3. 记录哪些样本调用工具后准确率提升；
4. 用这些样本做 few-shot prompt，观察模型是否更愿意调用工具。

## 面试表达

Toolformer 说明工具使用不只是推理时的工程技巧，也可以通过训练让模型学会。它的关键思想是用自监督方式筛选有价值的 API 调用样本，让模型学习何时、如何调用工具。

# 03 Reflexion: Language Agents with Verbal Reinforcement Learning

英文原版：`../papers_en/03_Reflexion_Language_Agents_with_Verbal_Reinforcement_Learning.pdf`

原始链接：https://arxiv.org/abs/2303.11366

## 中文精读

Reflexion 研究 Agent 如何从失败中学习。传统强化学习需要更新模型参数，而 Reflexion 不更新参数，它让 Agent 在任务失败后生成自然语言反思，把这段反思存入记忆，下一次类似任务时把反思放进上下文。

它的价值在于提供了一种轻量级“经验学习”方式：不训练模型，只通过文字经验改进行为。

## 中英术语对照

- Verbal Reinforcement Learning：语言形式的强化学习
- Reflection：反思
- Episodic Memory：情景记忆
- Trial：一次尝试
- Feedback Signal：反馈信号

## 核心要点

1. Agent 失败后总结原因和改进策略。
2. 反思以自然语言形式存储。
3. 下一次任务把反思作为上下文。
4. 适合任务可重复、反馈明确的环境。

## 局限

- 反思不一定正确；
- 如果反馈信号弱，反思可能变成自我安慰；
- 反思过多会污染上下文；
- 对一次性任务帮助有限。

## 最快复现实验

1. 设计 10 个需要多步推理的问题；
2. 第一次让 Agent 回答；
3. 对错误答案给出反馈；
4. 让 Agent 生成 reflection；
5. 第二次同类问题注入 reflection；
6. 比较准确率是否提升。

必须测试：

- 错误反思是否会让结果更差；
- 反思长度对效果的影响；
- 反思是否可复用到不同任务。

## 面试表达

Reflexion 的核心是把失败经验转成自然语言记忆，不更新模型参数也能改善后续表现。工程上它适合有明确反馈、可重复尝试的任务，但必须控制反思质量和上下文污染。

# 04 Generative Agents: Interactive Simulacra of Human Behavior

英文原版：`../papers_en/04_Generative_Agents_Interactive_Simulacra_of_Human_Behavior.pdf`

原始链接：https://arxiv.org/abs/2304.03442

## 中文精读

Generative Agents 构建了一个小镇模拟环境，让多个由 LLM 驱动的角色拥有记忆、计划和反思能力。每个 Agent 会观察环境，把观察写入记忆；系统根据相关性、近期性、重要性检索记忆；再周期性生成高层反思，指导未来行为。

这篇论文的重要性在于把 Agent 记忆系统具体化：不是简单保存聊天记录，而是有写入、检索、反思和计划。

## 中英术语对照

- Memory Stream：记忆流
- Reflection：反思
- Planning：计划
- Recency：近期性
- Relevance：相关性
- Importance：重要性

## 核心要点

1. 记忆不是原样塞入上下文，而要按分数检索。
2. 重要经历会触发高层反思。
3. Agent 的行为由当前观察、相关记忆和计划共同决定。
4. 多 Agent 社会行为可以从简单机制中涌现。

## 局限

- 社会模拟不等于生产任务成功；
- LLM 生成行为的真实性难评估；
- 成本较高；
- 记忆评分依赖模型判断。

## 最快复现实验

实现一个简化版个人日程 Agent：

1. 每天输入几条事件；
2. 对事件打 importance 分；
3. 检索相关记忆；
4. 生成明日计划；
5. 每 5 条高重要性记忆生成一次反思。

测试：

- 能否记住用户偏好；
- 能否根据新事件修改计划；
- 反思是否过度泛化。

## 面试表达

Generative Agents 的价值在于提出了记忆流、检索、反思、计划的组合机制。它说明长期行为一致性需要结构化记忆，而不是把完整历史全部放进 prompt。

# 05 Voyager: An Open-Ended Embodied Agent with Large Language Models

英文原版：`../papers_en/05_Voyager_Open_Ended_Embodied_Agent_with_LLMs.pdf`

原始链接：https://arxiv.org/abs/2305.16291

## 中文精读

Voyager 是 Minecraft 环境中的开放式 Agent。它不只是完成固定任务，而是不断探索、获取新技能，并把成功技能保存到 skill library。它包含自动课程生成、技能库、迭代提示机制。

这篇论文对 LLM Agent 的启发是：长期 Agent 需要积累可复用技能，而不是每次从零开始。

## 中英术语对照

- Open-ended Agent：开放式智能体
- Skill Library：技能库
- Curriculum：课程/任务生成
- Iterative Prompting：迭代提示
- Embodied Agent：具身智能体

## 核心要点

1. Agent 自动生成下一个探索目标。
2. 成功代码技能被保存和复用。
3. 环境反馈用于修正失败代码。
4. 技能积累让 Agent 能处理更复杂任务。

## 局限

- 依赖特定环境；
- 技能安全和泛化能力需要验证；
- 完整复现成本高；
- 技能库可能积累错误或冗余技能。

## 最快复现实验

不复现 Minecraft，可做本地文件任务：

1. 定义 10 个文件处理任务；
2. 每完成一个任务，把函数保存到 skill library；
3. 新任务先检索可复用函数；
4. 失败时让 Agent 修改函数；
5. 记录技能复用率。

测试：

- 技能是否真的复用；
- 旧技能是否误用；
- 技能库增长后检索是否变差。

## 面试表达

Voyager 的核心贡献是让 Agent 在开放环境中自我探索并积累技能库。它把 Agent 从一次性任务执行推进到持续学习和技能复用。

# 06 AutoGen: Enabling Next-Gen LLM Applications via Multi-Agent Conversation

英文原版：`../papers_en/06_AutoGen_Enabling_Next_Gen_LLM_Applications_via_Multi_Agent_Conversation.pdf`

原始链接：https://arxiv.org/abs/2308.08155

## 中文精读

AutoGen 把复杂 LLM 应用组织成多个可对话的 Agent。不同 Agent 可以扮演用户代理、助手、代码执行器、评论者等角色，通过消息传递协作完成任务。

它的重要性在于给多智能体工程提供了可编程抽象：角色、消息、工具、执行和终止条件。

## 中英术语对照

- Multi-Agent Conversation：多智能体对话
- Conversable Agent：可对话智能体
- Human-in-the-loop：人在回路
- Code Executor：代码执行器
- Group Chat：群组对话

## 核心要点

1. 多 Agent 通过对话协议协作。
2. 角色分工可以降低单 Agent 复杂度。
3. 工具执行和人类反馈可以嵌入对话。
4. 终止条件非常关键。

## 局限

- 多 Agent 容易增加 token 成本；
- 可能产生无效争论；
- 角色边界不清会导致责任混乱；
- 评估复杂。

## 最快复现实验

实现三 Agent：

1. Planner：拆任务；
2. Coder/Executor：执行；
3. Reviewer：检查结果；
4. 设置最大轮次；
5. 保存每轮消息。

测试：

- 单 Agent 与多 Agent 成功率；
- 平均 token 成本；
- Reviewer 是否真的发现错误；
- 最大轮次对结果的影响。

## 面试表达

AutoGen 说明多智能体系统的关键不是“多几个模型聊天”，而是设计角色、消息协议、工具执行和停止条件。多 Agent 适合复杂任务分工，但要控制成本和无效对话。

# 07 LATS: Language Agent Tree Search

英文原版：`../papers_en/07_LATS_Language_Agent_Tree_Search.pdf`

原始链接：https://arxiv.org/abs/2310.04406

## 中文精读

LATS 把语言 Agent 与树搜索结合。普通 Agent 往往沿着一条轨迹执行，走错后很难恢复；LATS 让模型生成多个候选行动，评估它们，再通过搜索选择更好的路径。

这篇论文体现了一个趋势：Agent 不一定要贪心地一步步走，可以在推理时探索多个路径。

## 中英术语对照

- Tree Search：树搜索
- Candidate Action：候选动作
- Value Function：价值评估
- Monte Carlo Tree Search：蒙特卡洛树搜索
- Backtracking：回溯

## 核心要点

1. 生成多个候选步骤，而不是只选一个。
2. 用模型或环境反馈评估候选。
3. 搜索能提升复杂任务表现。
4. 成本也会显著增加。

## 局限

- token 和工具调用成本高；
- 价值评估可能不可靠；
- 工程实现比 ReAct 复杂；
- 不适合简单任务。

## 最快复现实验

1. 给一个多步推理题；
2. 每一步生成 3 个候选；
3. 让模型给候选打分；
4. 选择分数最高路径；
5. 与贪心 ReAct 对比。

测试：

- 成功率是否提升；
- 成本提升多少；
- 打分错误是否导致搜索失败。

## 面试表达

LATS 的核心是用搜索缓解 Agent 单路径决策的脆弱性。它适合高价值复杂任务，但需要预算控制和可靠的候选评估。

# 08 Executable Code Actions Elicit Better LLM Agents

英文原版：`../papers_en/08_CodeAct_Executable_Code_Actions_Elicit_Better_LLM_Agents.pdf`

原始链接：https://arxiv.org/abs/2402.01030

## 中文精读

CodeAct 认为代码是更好的 Agent 行动空间。相比输出 JSON 调用单个工具，模型直接生成可执行 Python 代码，可以表达循环、条件、变量、组合多个库和工具。解释器返回错误或结果，Agent 再根据反馈修正。

这对软件 Agent 和数据分析 Agent 特别重要，因为代码本身就是一种强表达能力的行动语言。

## 中英术语对照

- Code Action：代码行动
- Executable Action：可执行动作
- Action Space：行动空间
- Python Interpreter：Python 解释器
- Self-debug：自我调试

## 核心要点

1. 用代码统一工具调用、计算和控制流。
2. Python 解释器提供确定性反馈。
3. 多工具组合比 JSON action 更自然。
4. 适合代码、数据、自动化任务。

## 局限

- 代码执行安全风险高；
- 需要沙箱、权限限制、超时；
- 对模型代码能力要求高；
- 可能生成破坏性操作。

## 最快复现实验

1. 给 Agent 一个 Python 沙箱；
2. 限制可用库；
3. 让它完成 CSV 分析、文件处理、API mock 调用；
4. 捕获 traceback；
5. 让 Agent 根据错误自修复。

必须测试：

- 超时；
- 文件越权；
- 恶意代码；
- 错误 traceback 是否能帮助修复。

## 面试表达

CodeAct 的关键观点是代码比 JSON 更适合作为复杂 Agent 的行动空间，因为代码能表达控制流和工具组合。但生产落地必须有沙箱、权限、超时和审计。

# 09 SWE-agent: Agent-Computer Interfaces Enable Automated Software Engineering

英文原版：`../papers_en/09_SWE_Agent_Agent_Computer_Interfaces_Enable_Automated_Software_Engineering.pdf`

原始链接：https://arxiv.org/abs/2405.15793

## 中文精读

SWE-agent 关注软件工程任务，强调 Agent-Computer Interface，即 Agent 与计算机环境交互的接口设计。它不是只让模型“猜代码”，而是提供合适的文件浏览、搜索、编辑、测试等命令，让 Agent 像工程师一样迭代。

这篇论文的启发是：Agent 能力不仅取决于模型，也取决于环境接口设计。

## 中英术语对照

- Agent-Computer Interface：智能体-计算机接口
- Repository：代码仓库
- Issue：问题描述
- Patch：补丁
- Test Feedback：测试反馈

## 核心要点

1. 软件 Agent 需要良好的命令接口。
2. 文件查看、搜索、编辑、测试是核心能力。
3. 测试反馈能帮助 Agent 修复错误。
4. 接口设计会显著影响任务成功率。

## 局限

- 真实大型仓库复杂；
- 测试不完整时容易误修；
- Agent 可能修改无关代码；
- 需要强约束和代码审查。

## 最快复现实验

1. 准备一个小 Python 项目和 5 个 bug；
2. 提供工具：list files、read file、search、apply patch、run tests；
3. 让 Agent 根据 bug 描述修复；
4. 保存 patch 和测试输出。

测试：

- 定位正确率；
- 补丁是否最小；
- 测试是否通过；
- 是否引入无关改动。

## 面试表达

SWE-agent 说明软件工程 Agent 的关键是接口设计。模型需要通过文件搜索、编辑、测试等工具与仓库交互，测试反馈是重要的外部验证信号。

# 10 A-MEM: Agentic Memory for LLM Agents

英文原版：`../papers_en/10_A_MEM_Agentic_Memory_for_LLM_Agents.pdf`

原始链接：https://arxiv.org/abs/2502.12110

## 中文精读

A-MEM 关注 Agentic Memory，即记忆不只是被动存储，而是参与 Agent 决策。长期 Agent 需要决定写入什么、如何组织、何时检索、如何更新。A-MEM 代表了 2025 年之后 Agent 记忆研究的重要方向。

## 中英术语对照

- Agentic Memory：智能体化记忆
- Memory Construction：记忆构建
- Memory Management：记忆管理
- Memory Retrieval：记忆检索
- Memory Update：记忆更新

## 核心要点

1. 记忆系统要服务任务，而不是简单存历史。
2. 写入、管理、读取都是可优化环节。
3. 记忆质量影响长期 Agent 的一致性。
4. 需要评估记忆对任务成功率的贡献。

## 局限

- 记忆评估困难；
- 记忆错误会长期影响行为；
- 隐私和权限问题突出；
- 不同任务需要不同记忆结构。

## 最快复现实验

1. 做一个用户偏好记忆系统；
2. 记录用户喜欢/不喜欢的选项；
3. 新任务检索相关偏好；
4. 用户改变偏好时更新旧记忆；
5. 统计偏好遵循率。

测试：

- 单会话记忆；
- 跨会话记忆；
- 冲突更新；
- 错误遗忘；
- 隐私删除请求。

## 面试表达

A-MEM 强调记忆是 Agent 的主动能力。生产系统中，记忆要有写入、检索、更新、删除和评估机制，否则长期使用会产生污染和不一致。

# 11 A Survey on Evaluation of LLM-based Agents

英文原版：`../papers_en/11_Survey_on_Evaluation_of_LLM_based_Agents.pdf`

原始链接：https://arxiv.org/abs/2503.16416

## 中文精读

这篇综述系统整理 LLM Agent 的评估。Agent 评估比普通问答更难，因为它涉及多步行动、工具调用、环境反馈、成本、安全和鲁棒性。只看最终答案对不对是不够的，还要看过程是否可靠、成本是否可接受、失败是否可解释。

## 中英术语对照

- Agent Evaluation：智能体评估
- Benchmark：基准测试
- Task Success Rate：任务成功率
- Trajectory Evaluation：轨迹评估
- Cost Efficiency：成本效率
- Robustness：鲁棒性

## 核心要点

1. Agent 评估要覆盖能力、应用、通用基准、框架工具。
2. 任务成功率只是一个指标。
3. 过程评估和成本评估同样重要。
4. 安全、鲁棒性、可复现是未来重点。

## 局限

- 综述不提供统一答案；
- benchmark 可能与真实生产差距大；
- LLM-as-judge 有偏差；
- 动态环境评估更难复现。

## 最快复现实验

为自己的 Agent 建 20 条测试集：

1. 简单任务；
2. 多步任务；
3. 工具错误任务；
4. 恶意输入任务；
5. 长上下文任务。

记录：

- 成功率；
- 平均步数；
- 工具调用次数；
- token 成本；
- 失败原因。

## 面试表达

Agent 评估必须从最终结果、执行轨迹、工具行为、成本、安全和鲁棒性多个维度看。生产上线前，我会构建固定测试集和 trace 日志，而不是只看 demo。

# 12 Mem0: Building Production-Ready AI Agents with Scalable Long-Term Memory

英文原版：`../papers_en/12_Mem0_Production_Ready_AI_Agents_with_Scalable_Long_Term_Memory.pdf`

原始链接：https://arxiv.org/abs/2504.19413

## 中文精读

Mem0 面向生产级长期记忆。它不是把全部历史塞进上下文，而是动态抽取、整合和检索重要信息。论文还讨论图记忆 Mem0g，用图结构表达实体关系。它的重点是准确率、延迟和 token 成本的平衡。

## 中英术语对照

- Long-Term Memory：长期记忆
- Memory Extraction：记忆抽取
- Memory Consolidation：记忆整合
- Graph Memory：图记忆
- LOCOMO Benchmark：长期对话记忆基准

## 核心要点

1. 全量上下文成本高且噪声大。
2. 生产记忆要抽取关键信息。
3. 图记忆适合关系和时间推理。
4. 评估要看准确率、延迟、token 成本。

## 局限

- 记忆抽取依赖模型质量；
- 图结构构建成本更高；
- 隐私、权限、删除机制需要工程补齐；
- benchmark 不一定覆盖所有业务场景。

## 最快复现实验

1. 准备 5 个用户的多轮对话；
2. 抽取偏好、事实、时间事件；
3. 存到向量库或 SQLite；
4. 查询时检索相关记忆；
5. 对比“全历史 prompt”和“记忆检索 prompt”。

测试：

- 准确率；
- prompt token 数；
- 延迟；
- 冲突事实更新；
- 多跳记忆问题。

## 面试表达

Mem0 的价值是把长期记忆做成可扩展工程系统：抽取、整合、检索，而不是依赖长上下文。它强调生产场景下准确率、延迟和 token 成本的平衡。

# 13 Agentic Reasoning for Large Language Models

英文原版：`../papers_en/13_Agentic_Reasoning_for_Large_Language_Models.pdf`

原始链接：https://arxiv.org/abs/2601.12538

## 中文精读

这是一篇 Agentic Reasoning 综述，把 LLM 从静态文本生成器转向能计划、行动、学习、协作的 Agent。它把领域分成基础 Agentic Reasoning、自我进化 Agentic Reasoning、集体多 Agent Reasoning。

这篇适合建立全局框架：Agentic Reasoning 不只是 prompt 技巧，而是一套包含环境交互、优化方式、工具、记忆、反馈、多智能体的研究方向。

## 中英术语对照

- Agentic Reasoning：智能体化推理
- Foundation：基础能力
- Evolution：自我进化
- Collaboration：协作
- In-context Reasoning：上下文内推理
- Post-training Reasoning：后训练推理

## 核心要点

1. Agentic Reasoning 连接 thought 与 action。
2. 基础层包括规划、搜索、工具使用。
3. 进化层包括反馈、记忆、适应。
4. 协作层包括多 Agent 角色、通信和协调。
5. 优化方式包括上下文编排和后训练。

## 局限

- 综述覆盖广，细节需要读原论文；
- 2026 方向仍在快速变化；
- 不同 benchmark 之间可比性有限；
- 工程落地还需要安全和评估体系。

## 最快复现实验

把自己的 Agent 项目映射到论文框架：

1. 它属于基础、进化还是协作？
2. 是否有工具使用？
3. 是否有记忆？
4. 是否有反馈学习？
5. 是否有多 Agent 协作？
6. 是否有评估？

输出一张能力矩阵。

## 面试表达

Agentic Reasoning 是让 LLM 在动态环境中通过计划、行动、反馈和协作完成任务的范式。它可以通过上下文编排实现，也可以通过后训练优化行为。

# 14 Agentic Artificial Intelligence: Architectures, Taxonomies, and Evaluation

英文原版：`../papers_en/14_Agentic_AI_Architectures_Taxonomies_and_Evaluation.pdf`

原始链接：https://arxiv.org/abs/2601.12560

## 中文精读

这篇论文从架构、分类和评估角度梳理 Agentic AI。它把 Agent 拆成感知、记忆、行动、规划、工具使用、协作等模块，并讨论从单循环 Agent 到层级多 Agent 系统的演进。

它适合作为架构设计参考：当你面试被要求“设计一个生产级 Agent 系统”时，可以用这篇论文的模块化视角组织答案。

## 中英术语对照

- Perception：感知
- Brain：认知/决策核心
- Planning：规划
- Action：行动
- Tool Use：工具使用
- Collaboration：协作
- Evaluation：评估

## 核心要点

1. Agentic AI 是从生成文本到自主行动的转变。
2. 模块化架构有助于设计和排查。
3. 工具协议、计算机使用、多智能体是重要方向。
4. 评估需要考虑可靠性、安全和成本。

## 局限

- 偏综述和分类；
- 对具体实现细节有限；
- 新产品和框架变化很快；
- 需要结合工程项目理解。

## 最快复现实验

用它的架构拆解你的项目：

| 模块 | 你的实现 | 风险 |
| --- | --- | --- |
| Perception | 输入解析/文件读取 | 数据污染 |
| Memory | 向量库/SQLite | 错误记忆 |
| Planning | 计划生成 | 计划不可执行 |
| Action | 工具调用 | 越权/超时 |
| Collaboration | 多 Agent | 成本上升 |
| Evaluation | 测试集/trace | 指标不完整 |

## 面试表达

这篇综述适合把 Agent 系统讲成模块化架构：感知输入、维护状态和记忆、规划任务、调用工具、接收反馈、必要时多 Agent 协作，最后用评估和安全机制约束整个闭环。

# 论文精读总复盘

## 如果只记 10 句话

1. ReAct 是 Agent 控制循环的基础。
2. Toolformer 说明工具使用可以被训练出来。
3. Reflexion 说明失败经验可以作为语言记忆复用。
4. Generative Agents 说明长期行为需要记忆、反思和计划。
5. Voyager 说明 Agent 可以积累可复用技能。
6. AutoGen 说明多 Agent 需要角色和通信协议。
7. LATS 说明复杂任务可以用搜索提升决策质量。
8. CodeAct 说明代码是强大的行动空间。
9. SWE-agent 说明接口设计决定软件 Agent 的能力上限。
10. Mem0/A-MEM 说明长期记忆是生产 Agent 的核心模块。

## 面试中最容易被问的综合题

**题目：请设计一个生产级 LLM Agent。**

答题结构：

1. 输入层：用户任务、文件、网页、历史上下文；
2. 规划层：任务拆解和预算；
3. 检索层：RAG 和长期记忆；
4. 工具层：白名单工具、schema、权限；
5. 执行层：ReAct/状态图；
6. 反思层：失败总结和可控记忆写入；
7. 评估层：任务成功率、成本、延迟、安全；
8. 安全层：prompt injection 防护、审计、高风险确认。
