# 12 个月 LLM Agent 长期研究计划（每天 1 小时）

## 固定每日结构

每天 1 小时建议固定拆分：

- 10 分钟：信息源扫描或复习昨天笔记；
- 35 分钟：当天主任务；
- 15 分钟：写输出，包括 3 句话总结、1 个问题、1 个面试表达。

如果当天任务是代码实验：

- 5 分钟：明确目标；
- 40 分钟：写代码/跑实验；
- 15 分钟：记录结果、失败原因、下一步。

## 月度路线总览

| 月份 | 主题 | 月度产出 |
| --- | --- | --- |
| 第 1 月 | LLM 基础与研究方法 | 一份 LLM 基础笔记 + 10 道基础面试题 |
| 第 2 月 | Prompt、上下文工程与结构化输出 | 一个提示词/结构化输出实验 |
| 第 3 月 | RAG 基础与评估 | 一个带引用的本地知识库问答 Demo |
| 第 4 月 | Agent 基础：ReAct 与工具调用 | 一个可调用 3 个工具的 Agent |
| 第 5 月 | Agent 记忆：短期、长期、图记忆 | 一个带长期记忆的个人助手原型 |
| 第 6 月 | 规划、反思与搜索 | 一个能计划、执行、反思的小型任务 Agent |
| 第 7 月 | 多智能体协作 | 一个 Planner + Executor + Reviewer 多 Agent Demo |
| 第 8 月 | 框架与协议：LangGraph/AutoGen/MCP | 一个图式编排 Agent |
| 第 9 月 | Agent 评估、安全与可观测性 | 一套 20 条测试集 + trace 日志 |

# 第 1 月：LLM 基础与研究方法

目标：理解 LLM 的基本机制，建立读论文和追踪资料的方法。

## 第 1 周：建立学习系统与 LLM 全局认识

- 周一：阅读 `../00_总览/能力地图与使用说明.md`，写下自己当前能力短板。
- 周二：学习 Transformer 总体结构，重点理解 Attention、FFN、残差、LayerNorm。
- 周三：学习 token、embedding、位置编码，写 5 个面试常问概念解释。
- 周四：学习预训练目标，理解 next token prediction 为什么有效。
- 周五：阅读一篇中文 LLM 总览文章，按“问题-方法-指标-局限”做笔记。
- 周六：整理 1 页“LLM 从输入到输出的流程图”。
- 周日：复盘本周，口头回答“Transformer 为什么适合语言建模？”。

## 第 2 周：后训练、对齐与推理能力

- 周一：学习 SFT，理解指令微调数据如何影响模型行为。
- 周二：学习 RLHF，理解 reward model 和 PPO 的基本流程。
- 周三：学习 DPO，比较 DPO 与 RLHF 的训练目标差异。
- 周四：学习 CoT、Self-Consistency、Tree-of-Thought 的直觉。
- 周五：学习 reasoning model 与 test-time scaling 的概念。
- 周六：整理表格：SFT/RLHF/DPO/RLVR 的区别、优点、风险。
- 周日：做 5 道基础面试题：预训练、微调、对齐、推理、幻觉。

## 第 3 周：长上下文、幻觉与检索增强

- 周一：学习上下文窗口和 token 成本，理解长上下文的限制。
- 周二：学习幻觉产生原因：训练分布、概率生成、缺少事实校验。
- 周三：学习 RAG 的基本思想，理解为什么检索能降低事实错误。
- 周四：比较长上下文、RAG、记忆三者的区别。
- 周五：阅读一篇 RAG 中文教程，记录系统模块。
- 周六：画出“用户问题 -> 检索 -> 重排 -> 生成 -> 引用”的流程。
- 周日：面试复述：“为什么长上下文不能完全替代 RAG？”。

## 第 4 周：论文阅读方法与第一轮总结

- 周一：阅读 ReAct 论文摘要和引言，只关注它解决什么问题。
- 周二：阅读 ReAct 方法部分，理解 reasoning/action/observation。
- 周三：阅读 ReAct 实验表格，记录它在哪些任务上有效。
- 周四：阅读一篇 ReAct 中文解读，校正自己的理解。
- 周五：写 1 页 ReAct 精读笔记。
- 周六：整理第 1 月所有面试题，补齐不会回答的问题。
- 周日：月度复盘：写“我如何理解 LLM Agent 的起点”。

# 第 2 月：Prompt、上下文工程与结构化输出

目标：掌握提示词、上下文选择、结构化输出和基本防错。

## 第 1 周：Prompt 基础

- 周一：学习 zero-shot、few-shot、role prompting 的区别。
- 周二：练习把一个开放问题改写成结构化 prompt。
- 周三：学习约束输出：JSON、Markdown、表格、schema。
- 周四：练习让模型输出可解析 JSON，并记录失败情况。
- 周五：学习 prompt 中的上下文顺序、示例质量、反例约束。
- 周六：整理 5 个常用 prompt 模板：总结、抽取、分类、改写、评估。
- 周日：面试复述：“Prompt 工程和上下文工程有什么区别？”。

## 第 2 周：结构化输出与工具参数

- 周一：学习 JSON Schema 的基本字段：type、required、enum、description。
- 周二：设计一个天气查询工具 schema。
- 周三：设计一个搜索工具 schema。
- 周四：设计一个数据库查询工具 schema，重点考虑权限和参数校验。
- 周五：学习函数调用失败原因：参数缺失、类型错误、幻觉工具。
- 周六：写一个“工具参数校验清单”。
- 周日：面试复述：“为什么工具调用不能只靠 prompt 约束？”。

## 第 3 周：上下文工程

- 周一：学习上下文来源：系统指令、用户消息、历史、检索结果、工具结果。
- 周二：学习上下文压缩：摘要、过滤、排序、去重。
- 周三：学习外部内容隔离：把网页/文档当数据，不当指令。
- 周四：分析一次 Agent 失败，判断是上下文不足还是上下文污染。
- 周五：阅读国内关于上下文工程/Manus/Agent 的文章。
- 周六：写一份“上下文进入 prompt 前的处理流程”。
- 周日：面试复述：“如何治理 Agent 的上下文窗口？”。

## 第 4 周：小实验

- 周一：准备 10 条测试输入，覆盖正常、边界、恶意输入。
- 周二：写一个 prompt，让模型把自然语言需求转成 JSON。
- 周三：加入 schema 校验，记录不合法输出。
- 周四：加入重试和错误提示，观察改善。
- 周五：写实验报告：成功率、失败类型、改进点。
- 周六：把实验整理成 README。
- 周日：月度复盘：形成“Prompt/上下文工程面试表达”。

# 第 3 月：RAG 基础与评估

目标：能做一个带引用、可评估的本地知识库问答 Demo。

## 第 1 周：RAG 架构

- 周一：学习 RAG 五模块：加载、切分、索引、检索、生成。
- 周二：学习文档切分策略，比较固定长度和标题层级切分。
- 周三：学习 embedding 和向量相似度，理解余弦相似度。
- 周四：学习 BM25 与向量检索的区别。
- 周五：学习 hybrid search 和 rerank。
- 周六：画出你的 RAG 系统架构图。
- 周日：面试复述：“RAG 系统有哪些模块？”。

## 第 2 周：构建最小 RAG

- 周一：选择 3 篇本地 PDF 或 Markdown 作为知识库。
- 周二：写文档解析和切分脚本。
- 周三：生成向量并存入本地索引。
- 周四：实现 top-k 检索，打印命中文档片段。
- 周五：把检索结果拼接进 prompt 生成答案。
- 周六：加入引用来源和片段编号。
- 周日：记录 5 个失败问题。

## 第 3 周：RAG 评估

- 周一：制作 20 条问答测试集。
- 周二：评估检索命中率：答案片段是否被召回。
- 周三：评估生成质量：是否引用、是否忠实。
- 周四：测试不同 chunk size 的效果。
- 周五：测试 top-k 和 rerank 的影响。
- 周六：整理评估表格。
- 周日：面试复述：“如何评估 RAG 好不好？”。

## 第 4 周：RAG 与 Agentic RAG

- 周一：学习 Agentic RAG：让模型决定是否检索、检索什么、是否二次检索。
- 周二：设计一个“先判断是否需要检索”的路由器。
- 周三：设计一个“答案不足时重新检索”的循环。
- 周四：学习 RAG 风险：错误切分、召回失败、引用幻觉、检索污染。
- 周五：写 RAG 项目 README。
- 周六：做 30 分钟项目口头讲解。
- 周日：月度复盘：RAG 项目能否放进简历。
