# 模型与工具选型指南

## 一、选型的第一原则

不要问“哪个模型最好”，要问：

1. 我的任务是什么？
2. 是否需要私有化？
3. 是否主要是中文？
4. 是否需要多模态？
5. 是否需要写代码或改代码？
6. 是否需要长上下文？
7. 是否需要工具调用？
8. 每月预算是多少？
9. 是否有安全合规要求？
10. 是否需要团队统一治理？

## 四、个人学习者推荐路线

### 第一阶段：低成本理解能力

- 模型：Qwen、DeepSeek、Gemini Flash；
- 工具：Cursor 免费/Pro、Continue、Aider；
- 学习：RAG、ReAct、工具调用、面试题；
- 目标：能做项目，不追求最贵模型。

### 第二阶段：体验前沿能力

- 模型：Claude、GPT、Gemini Pro；
- 工具：Claude Code、Codex CLI、Cursor；
- 学习：复杂代码、长任务、Agent trace；
- 目标：理解前沿模型和普通模型差距。

### 第三阶段：形成作品集

- 项目 1：企业 RAG；
- 项目 2：工具调用 Agent；
- 项目 3：长期记忆助手；
- 项目 4：软件工程 Agent；
- 面试：每个项目必须有指标和失败案例。

## 五、企业生产选型

### 1. 如果企业已有 Microsoft 生态

推荐：

- Microsoft Copilot；
- GitHub Copilot；
- Azure OpenAI；
- Semantic Kernel；
- Azure AI Search。

原因：

- 权限和身份体系一致；
- GitHub/Office/Teams 集成；
- 合规路径清晰。

风险：

- 成本；
- 产品线复杂；
- 对非 Microsoft 工作流不一定最佳。

### 2. 如果企业已有 Google 生态

推荐：

- Gemini；
- Vertex AI；
- Gemini Workspace；
- Google Cloud Search/BigQuery；
- Gemini CLI/Jules。

原因：

- 多模态和长上下文；
- Workspace 集成；
- 高吞吐和云服务。

### 3. 如果企业在 AWS

推荐：

- Bedrock；
- Claude / Nova / Titan / Llama 等多模型；
- Amazon Q Developer；
- Bedrock Agents。

原因：

- 多模型选择；
- AWS 权限和云资源；
- 企业部署成熟。

### 4. 如果企业在国内云

推荐：

- 阿里云百炼 + Qwen；
- 百度千帆 + 文心；
- 火山方舟 + 豆包；
- 腾讯云 + 混元；
- 私有化可选 Qwen/DeepSeek/GLM。

原因：

- 网络和合规；
- 中文能力；
- 本地支持；
- 成本可控。

## 六、AI 编程工具组合

### 组合 1：最通用

```text
Cursor + Claude Code + GitHub Copilot
```

适合：

- 日常开发；
- 复杂重构；
- GitHub 团队。

### 组合 2：OpenAI 生态

```text
ChatGPT/Codex + Codex CLI + GitHub
```

适合：

- 已有 OpenAI 订阅；
- 需要 agentic coding；
- 需要云端后台任务。

### 组合 3：开源/低成本

```text
Continue/Cline + Aider + Qwen/DeepSeek/Ollama
```

适合：

- 本地代码安全；
- 成本敏感；
- 想自定义模型。

### 组合 4：企业标准化

```text
GitHub Copilot Enterprise + Claude Code/Codex CLI 白名单 + 内部评估平台
```

适合：

- 大研发团队；
- 需要合规；
- 需要统一审计。

## 七、RAG 选型建议

### 小型知识库

- 文档：Markdown/PDF；
- 向量库：FAISS/Chroma；
- 模型：Qwen/DeepSeek/GPT/Gemini；
- 框架：LlamaIndex 或 LangChain；
- 评估：人工 + 20 条测试集。

### 企业知识库

- 文档解析：结构化 parser；
- 检索：Hybrid Search；
- 重排：reranker；
- 权限：检索前过滤；
- 引用：强制 citation；
- 评估：Recall@k、Faithfulness、权限泄露；
- 监控：日志、trace、反馈闭环。

### 复杂知识网络

- GraphRAG；
- 实体抽取；
- 关系图；
- 社区摘要；
- 适合组织结构、产品文档、研究报告。

## 八、Agent 选型建议

### 简单 Agent

使用：

- Function calling；
- 固定工具；
- 最大步数；
- JSON trace。

### 中等复杂 Agent

使用：

- LangGraph；
- 状态机；
- 工具权限；
- Memory；
- RAG；
- 评估集。

### 复杂 Agent

使用：

- 多模型路由；
- Planner/Executor/Reviewer；
- MCP 工具注册；
- 预算控制；
- sandbox；
- 人类确认；
- 回归测试。

## 九、什么时候不要用 Agent

以下场景不建议上 Agent：

1. 简单一次性问答；
2. 明确规则可用传统代码解决；
3. 高风险动作但没有人工确认；
4. 没有测试集；
5. 没有日志和审计；
6. 工具权限无法限制；
7. 预算无法控制；
8. 用户无法接受偶发失败。

## 十、未来趋势判断

### 1. 模型能力会继续趋同

前沿模型差距会越来越小，任务适配、价格、生态和可靠性比单一分数更重要。

### 2. 开源模型会持续压低成本

Qwen、DeepSeek、Llama、Mistral 等开放模型会让很多企业不再必须用最贵闭源模型。

### 3. AI 编程会从补全走向交付

未来开发者工作流会是：

```text
人类定义需求和验收标准
Agent 生成计划和代码
工具运行测试
人类 review 和合并
```

### 4. Agent 安全会成为核心岗位能力

懂 prompt、RAG、工具调用还不够，还要懂：

- 权限；
- 审计；
- sandbox；
- prompt injection；
- 数据隔离；
- 回归测试。

### 5. 企业会从“买模型”转向“建 AI 工作流”

模型只是底座，真正产生价值的是：

- 数据治理；
- 工具接入；
- 流程改造；
- 员工培训；
- 评估体系；
- 安全合规。

## 十一、最终建议

### 个人

不要纠结一个模型。建议：

- 用 Cursor 做日常；
- 用 Claude Code/Codex CLI 学 Agent coding；
- 用 Qwen/DeepSeek 学开源私有化；
- 用 GPT/Claude/Gemini 体验前沿；
- 做 3 个可展示项目。

### 企业

不要先大规模采购。建议：

1. 选 3 个高价值场景；
2. 建测试集；
3. 横评 3-5 个模型；
4. 计算成本；
5. 做安全审计；
6. 小范围试点；
7. 再平台化推广。

### 面试准备

必须能回答：

1. 大模型发展经历了哪些阶段？
2. OpenAI、Anthropic、Google、Meta、Qwen、DeepSeek 各自优势是什么？
3. RAG 和长上下文怎么选？
4. Agent 和 Chatbot 区别是什么？
5. AI 编程工具 Cursor、Copilot、Claude Code、Codex CLI 有什么区别？
6. 企业如何选模型？
7. Agent 上线前要做哪些评估？
