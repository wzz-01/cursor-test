# 高级项目路线与能力考核标准

## 总体目标

完成 4 个可展示项目：

1. 高级企业知识库 RAG；
2. 工具调用与状态图 Agent；
3. 长期记忆个人助手；
4. 软件工程 Agent / 研究助手二选一。

每个项目都必须具备：

- README；
- 架构图；
- 运行方式；
- 测试集；
- trace 日志；
- 指标表；
- 失败案例；
- 安全说明；
- 面试讲解稿；
- 简历表达。

## 项目 1：高级企业知识库 RAG

### 目标

构建一个支持多文档、多权限、引用、拒答和评估的 RAG 系统。

### 模块

1. 文档接入：PDF、Markdown、网页；
2. 文档解析：保留标题、表格、段落结构；
3. Chunking：标题层级 + 语义切分；
4. 索引：向量索引 + BM25；
5. 检索：Hybrid Search；
6. 重排：rerank；
7. 生成：带引用回答；
8. 权限：用户角色过滤；
9. 评估：检索、生成、引用、拒答；
10. 安全：防 prompt injection。

### 测试集

至少 50 条：

- 20 条答案直接在文档中；
- 10 条需要多片段组合；
- 5 条需要拒答；
- 5 条权限隔离；
- 5 条相似但错误证据；
- 5 条恶意指令。

### 指标

| 指标 | 目标 |
| --- | --- |
| Recall@5 | >= 80% |
| 引用准确率 | >= 85% |
| 拒答正确率 | >= 80% |
| 权限泄露 | 0 |
| 平均延迟 | 可解释并可优化 |

### 面试表达

```text
我做的是一个企业知识库 RAG，不只是向量库问答。
系统包含文档解析、混合检索、重排、引用生成、权限过滤和评估。
我重点解决了召回失败、引用幻觉和权限泄露三个问题，并用 50 条测试集评估 Recall@5、引用准确率和拒答率。
```

## 项目 2：工具调用与状态图 Agent

### 目标

实现一个基于状态图的 Agent，能够安全调用搜索、计算、文件、数据库等工具。

### 模块

1. Agent State；
2. Planner Node；
3. Tool Selection Node；
4. Tool Execution Node；
5. Observation Node；
6. Reflection Node；
7. Finish Node；
8. Trace Logger；
9. Budget Controller；
10. Safety Guard。

### 测试集

至少 60 条：

- 15 条单工具；
- 15 条多工具；
- 10 条工具失败；
- 10 条恶意工具诱导；
- 5 条超预算；
- 5 条需要追问。

### 指标

| 指标 | 目标 |
| --- | --- |
| 任务成功率 | >= 75% |
| 工具参数合法率 | >= 95% |
| 无效工具调用率 | <= 15% |
| 安全违规 | 0 |
| trace 覆盖率 | 100% |

### 面试表达

```text
我没有使用完全自由循环，而是用状态图组织 Agent。
每个节点职责明确，工具调用经过 schema 校验、权限检查和超时控制。
所有执行步骤都会写入 trace，因此可以定位失败发生在计划、工具选择、执行还是生成阶段。
```

## 项目 3：长期记忆个人助手

### 目标

实现能跨会话保存偏好、事实和任务历史，并能处理冲突更新与删除请求的 Agent。

### 模块

1. Memory Extractor；
2. Memory Classifier；
3. Memory Store；
4. Memory Retriever；
5. Conflict Detector；
6. Update Manager；
7. Forget/Delete Manager；
8. Privacy Guard；
9. Memory Evaluation。

### Memory Schema

```json
{
  "id": "memory_id",
  "user_id": "user_id",
  "type": "preference|fact|task|constraint|skill",
  "content": "记忆内容",
  "source": "来源",
  "confidence": 0.9,
  "created_at": "时间",
  "updated_at": "时间",
  "status": "active|expired|deleted"
}
```

### 测试集

至少 50 条：

- 偏好记忆；
- 事实记忆；
- 偏好改变；
- 事实冲突；
- 多用户隔离；
- 删除请求；
- 长期未使用记忆；
- 恶意记忆注入。

### 指标

| 指标 | 目标 |
| --- | --- |
| 偏好召回准确率 | >= 85% |
| 冲突更新正确率 | >= 80% |
| 删除后引用率 | 0 |
| 跨用户泄露 | 0 |
| 错误记忆写入率 | <= 5% |

### 面试表达

```text
我把记忆当成完整生命周期系统，而不是简单保存聊天历史。
每条记忆都有类型、来源、置信度、时间和状态。
系统支持冲突检测、过期、删除和权限隔离，并通过多轮测试集评估偏好召回和更新正确率。
```

## 项目 4A：软件工程 Agent

### 目标

让 Agent 根据 issue 搜索代码、定位问题、生成最小 patch、运行测试并输出报告。

### 工具

- list_files；
- search_code；
- read_file；
- apply_patch；
- run_tests；
- git_diff；
- final_report。

### 安全规则

- 禁止危险 shell 命令；
- 限制读写目录；
- patch 必须最小化；
- 测试失败不能声称成功；
- 所有 diff 必须可审计。

### 指标

| 指标 | 目标 |
| --- | --- |
| 定位正确率 | >= 70% |
| 测试通过率 | >= 60% |
| 无关修改率 | <= 10% |
| 危险命令执行 | 0 |

### 面试表达

```text
软件工程 Agent 的关键不是让模型直接生成完整代码，而是设计 Agent-Computer Interface。
我提供搜索、读取、编辑、测试等受控工具，让 Agent 通过测试反馈迭代修复。
```

## 项目 4B：AI 研究助手

### 目标

自动整理论文、博客和项目，生成中文精读、趋势报告和面试题。

### 模块

- PDF Parser；
- Paper Metadata Extractor；
- RAG Index；
- Summary Agent；
- Citation Checker；
- Trend Classifier；
- Interview Question Generator；
- Weekly Report Writer。

### 指标

| 指标 | 目标 |
| --- | --- |
| 论文要点覆盖率 | >= 80% |
| 引用正确率 | >= 90% |
| 幻觉率 | <= 5% |
| 面试题可用率 | >= 80% |

### 面试表达

```text
研究助手的核心是把论文阅读流程结构化。
系统会抽取问题、方法、实验、局限和引用，并将论文按 RAG、Agent、Memory、Evaluation 等主题归类。
```

## 能力考核矩阵

| 能力 | 初级 | 中级 | 高级 |
| --- | --- | --- | --- |
| LLM 基础 | 能解释 Transformer | 能解释后训练和推理 | 能结合成本和任务选模型 |
| RAG | 能做向量问答 | 能做混合检索和评估 | 能做权限、GraphRAG、Agentic RAG |
| Agent | 能写 ReAct loop | 能做状态图和工具安全 | 能做多 Agent、预算、trace |
| Memory | 能保存历史 | 能做检索和更新 | 能做冲突、遗忘、隐私治理 |
| Evaluation | 能人工测试 | 有固定测试集 | 有 trace、回归、指标面板 |
| Safety | 知道注入风险 | 有工具权限 | 有红队测试和审计 |
| 面试表达 | 能背概念 | 能讲项目 | 能讲权衡、失败和指标 |

5. 如果上线，最大风险是什么？
6. 面试时如何用 3 分钟讲清楚？
