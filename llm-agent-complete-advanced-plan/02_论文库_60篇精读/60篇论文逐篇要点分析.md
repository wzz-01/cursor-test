# 60+ 篇论文逐篇要点分析

> 每篇按“核心问题 -> 关键贡献 -> 怎么学习 -> 面试价值”整理。精读时请配合 `60篇论文完整清单与学习顺序.md` 使用。

## 01 Attention Is All You Need

- 核心问题：如何不用 RNN/CNN 也能建模序列。
- 关键贡献：提出 Transformer，用 Self-Attention、Multi-Head Attention、Position Encoding、FFN 组成可并行扩展的序列模型。
- 怎么学习：重点看 Encoder/Decoder、Scaled Dot-Product Attention 公式、多头注意力为什么能学习不同关系。
- 面试价值：解释 Transformer、Attention 复杂度、为什么 LLM 基于 Transformer。
- 落地注意：长上下文成本高，Agent 的上下文管理必须考虑 token 和注意力噪声。

## 02 BERT

- 核心问题：如何通过双向上下文学习通用语言表示。
- 关键贡献：MLM + NSP，推动预训练-微调范式。
- 怎么学习：理解 BERT 与 GPT 的差异：BERT 更适合理解任务，GPT 更适合生成任务。
- 面试价值：解释 Encoder-only、Decoder-only、Encoder-Decoder 的区别。
- 落地注意：RAG 中 embedding/rerank 模型常来自 BERT 类架构。

## 03 GPT-3 / Language Models are Few-Shot Learners

- 核心问题：规模扩大后，模型是否能通过 prompt 做少样本任务。
- 关键贡献：展示 few-shot/in-context learning 能力，强化 scaling 对能力涌现的影响。
- 怎么学习：关注 zero-shot、one-shot、few-shot，以及任务性能随规模变化。
- 面试价值：解释 in-context learning、为什么 prompt 有效。
- 落地注意：Agent prompt 示例质量会显著影响工具调用稳定性。

## 04 T5

- 核心问题：能否把所有 NLP 任务统一成 text-to-text。
- 关键贡献：统一输入输出格式，为指令化和任务统一提供思想基础。
- 怎么学习：看任务如何被转成文本到文本。
- 面试价值：解释统一范式对大模型指令学习的启发。
- 落地注意：Agent 的结构化任务也可以转成统一文本接口。

## 05 Scaling Laws

- 核心问题：模型大小、数据量、计算量如何影响 loss。
- 关键贡献：提出经验 scaling law，帮助预测扩大模型的收益。
- 怎么学习：关注 power law，而不是记公式细节。
- 面试价值：解释为什么大模型能力随规模增强，以及 scaling 的边界。
- 落地注意：能力提升不只靠参数，数据质量、后训练、工具和系统设计同样关键。

## 06 Chinchilla

- 核心问题：固定计算预算下，参数和数据如何平衡。
- 关键贡献：指出很多模型训练 token 不足，数据规模同样重要。
- 怎么学习：理解 compute-optimal 的含义。
- 面试价值：回答“模型越大越好吗”。
- 落地注意：企业训练/微调更应关注数据质量和任务匹配。

## 07 LLaMA

- 核心问题：如何训练高效开源基础模型。
- 关键贡献：用高质量数据和合理规模训练强基座，推动开源生态。
- 怎么学习：关注数据、token、模型规模和开源影响。
- 面试价值：解释开源基座模型生态。
- 落地注意：很多 Agent 系统可基于开源模型做私有化部署。

## 08 Llama 2

- 核心问题：如何把基础模型后训练成聊天模型并考虑安全。
- 关键贡献：公开 Chat 模型训练、安全评估和 RLHF 流程。
- 怎么学习：重点看 SFT、RLHF、安全数据、评估。
- 面试价值：解释 chat model 和 base model 的区别。
- 落地注意：Agent 需要 chat model 的指令遵循能力，但仍需系统层安全。

## 09 Mistral 7B

- 核心问题：小模型如何做到高效率高性能。
- 关键贡献：滑动窗口注意力、GQA 等高效设计。
- 怎么学习：理解为什么小模型在工程上重要。
- 面试价值：回答“什么时候用小模型”。
- 落地注意：Agent 可用小模型做路由、分类、简单工具选择，降低成本。

## 10 Mixtral of Experts

- 核心问题：如何用 MoE 提高容量同时控制推理成本。
- 关键贡献：稀疏激活专家模型。
- 怎么学习：理解 router、expert、稀疏激活。
- 面试价值：解释 MoE 与 dense model 的区别。
- 落地注意：MoE 可提升能力，但部署和延迟稳定性更复杂。

## 11 DeepSeek-R1

- 核心问题：如何通过强化学习激发长链推理能力。
- 关键贡献：展示 RL 对推理行为的塑造，推动开源推理模型热潮。
- 怎么学习：重点理解 RL、冷启动数据、蒸馏、长 CoT。
- 面试价值：解释 reasoning model、RLVR、test-time scaling。
- 落地注意：推理模型适合复杂规划，但 token 成本和延迟更高。

## 12 InstructGPT

- 核心问题：如何让语言模型更符合人类指令。
- 关键贡献：SFT -> Reward Model -> RLHF 的经典流程。
- 怎么学习：画出三阶段训练流程。
- 面试价值：几乎必问：RLHF 是什么。
- 落地注意：对齐提升有用性，但不能替代业务规则和工具安全。

## 13 Constitutional AI

- 核心问题：如何减少对人工偏好标注的依赖并提升安全。
- 关键贡献：用原则/宪法让 AI 生成反馈，即 RLAIF。
- 怎么学习：看 critique 和 revision 过程。
- 面试价值：解释 AI feedback 与 human feedback 的区别。
- 落地注意：Agent 安全策略可借鉴“原则 + 审查 + 修订”。

## 14 Self-Instruct

- 核心问题：如何自动生成指令数据扩充训练集。
- 关键贡献：用模型自生成任务、过滤、构造 instruction data。
- 怎么学习：关注数据生成和过滤流程。
- 面试价值：解释指令数据如何构建。
- 落地注意：Agent 工具调用数据也可用自生成方式扩充，但要严格过滤。

## 15 DPO

- 核心问题：是否能不用显式 reward model 做偏好优化。
- 关键贡献：把偏好优化转成直接分类式目标。
- 怎么学习：理解 preferred/rejected pair。
- 面试价值：比较 SFT、RLHF、DPO。
- 落地注意：适合偏好数据充分、想简化 RLHF 流程的场景。

## 16 KTO

- 核心问题：偏好数据不总是成对，如何学习人类偏好。
- 关键贡献：基于前景理论建模 desirable/undesirable。
- 怎么学习：作为 DPO 扩展了解。
- 面试价值：展示你了解偏好优化前沿。
- 落地注意：不是 Agent 入门必需，先掌握 DPO。

## 17 ORPO

- 核心问题：能否在一个目标里同时做 SFT 和偏好优化。
- 关键贡献：无需 reference model 的偏好优化。
- 怎么学习：理解它简化训练链路的动机。
- 面试价值：补充偏好优化方法谱系。
- 落地注意：工程中要看数据质量和实际收益。

## 18 Post-training Survey

- 核心问题：后训练技术体系如何组织。
- 关键贡献：系统梳理 SFT、RLHF、DPO、推理强化、多模态后训练。
- 怎么学习：作为地图读，不必逐节细抠。
- 面试价值：建立后训练全局框架。
- 落地注意：Agent 能力可来自模型后训练，也可来自外部系统编排。

## 19 Chain-of-Thought

- 核心问题：如何让模型显式进行多步推理。
- 关键贡献：通过示例诱导中间推理步骤。
- 怎么学习：对比 direct answer 和 CoT。
- 面试价值：解释 CoT 的作用和局限。
- 落地注意：CoT 不保证正确，生产中更需要外部验证。

## 20 Self-Consistency

- 核心问题：单条 CoT 不稳定怎么办。
- 关键贡献：采样多条推理路径，用答案投票提高鲁棒性。
- 怎么学习：理解“多样路径 + 聚合”。
- 面试价值：回答如何提升推理稳定性。
- 落地注意：提升准确率但增加成本，适合高价值任务。

## 21 Least-to-Most Prompting

- 核心问题：复杂问题如何逐步拆解。
- 关键贡献：先分解子问题，再依次求解。
- 怎么学习：重点看任务分解范式。
- 面试价值：连接 Agent planning。
- 落地注意：Agent 任务规划常用类似思想。

## 22 STaR

- 核心问题：如何用模型生成的推理过程反过来训练模型。
- 关键贡献：自举生成 rationale 并迭代训练。
- 怎么学习：理解 bootstrapping。
- 面试价值：解释 reasoning data 如何构造。
- 落地注意：自生成数据要防止错误推理被强化。

## 23 Tree of Thoughts

- 核心问题：线性 CoT 不足以解决需要探索的问题。
- 关键贡献：把推理过程扩展成树，支持候选生成、评估、搜索。
- 怎么学习：画出节点、候选、评估、回溯。
- 面试价值：解释 test-time search。
- 落地注意：适合复杂任务，但成本高。

## 24 Graph of Thoughts

- 核心问题：有些推理结构不是树，而是图。
- 关键贡献：用图表达中间思想之间的组合和复用。
- 怎么学习：作为 ToT 的扩展理解。
- 面试价值：说明你知道推理结构不止链式。
- 落地注意：工程复杂度高，先掌握 ToT。

## 25 LLM Reasoning Survey

- 核心问题：推理技术前沿如何分类。
- 关键贡献：把推理分成 inference scaling、learning to reason、agentic systems。
- 怎么学习：作为推理地图使用。
- 面试价值：回答“推理模型发展趋势”。
- 落地注意：区分模型内部推理和 Agent 外部编排。

## 26 Reasoning LLM Survey

- 核心问题：System 1/System 2 如何映射到 LLM 推理。
- 关键贡献：总结快思考、慢思考、长 CoT、训练与推理时扩展。
- 怎么学习：和 DeepSeek-R1、ToT 对照。
- 面试价值：解释为什么推理模型会更慢但更强。
- 落地注意：复杂任务使用推理模型，简单任务用小模型路由。

## 27 RAG

- 核心问题：参数知识不够实时或不够准确怎么办。
- 关键贡献：检索外部文档并增强生成。
- 怎么学习：理解 retriever-generator 结构。
- 面试价值：RAG 是必问题。
- 落地注意：完整 RAG 包含解析、切分、召回、重排、引用、评估。

## 28 REALM

- 核心问题：能否在预训练阶段加入检索。
- 关键贡献：检索增强预训练。
- 怎么学习：了解早期 retrieval-augmented LM。
- 面试价值：说明 RAG 不只是应用层拼接。
- 落地注意：企业多采用应用层 RAG，而非重新预训练。

## 29 DPR

- 核心问题：开放域问答如何高效检索相关段落。
- 关键贡献：双塔 dense retrieval。
- 怎么学习：理解 query encoder、passage encoder、in-batch negative。
- 面试价值：解释向量检索基础。
- 落地注意：embedding 模型选择直接影响 RAG 召回。

## 30 FiD

- 核心问题：如何让生成模型利用多个检索段落。
- 关键贡献：Fusion-in-Decoder。
- 怎么学习：看多文档信息融合。
- 面试价值：解释检索结果如何进入生成。
- 落地注意：多片段拼接会带来噪声和成本。

## 31 Atlas

- 核心问题：检索增强模型如何提升少样本学习。
- 关键贡献：大规模 retrieval augmented LM。
- 怎么学习：关注检索对 few-shot 的作用。
- 面试价值：补充 RAG 发展脉络。
- 落地注意：检索库质量和更新机制关键。

## 32 HyDE

- 核心问题：没有相关性标注时如何提升 dense retrieval。
- 关键贡献：先生成 hypothetical document，再用它检索。
- 怎么学习：理解 query expansion。
- 面试价值：回答“用户问题太短检索不好怎么办”。
- 落地注意：生成的假文档可能引入偏差。

## 33 Self-RAG

- 核心问题：模型何时检索、如何评价检索和答案。
- 关键贡献：引入 reflection tokens，让模型学习 retrieve、critique。
- 怎么学习：关注自反思控制点。
- 面试价值：连接 RAG 与 Agent。
- 落地注意：实际系统可用路由器判断是否检索。

## 34 CRAG

- 核心问题：检索结果错误或不完整时怎么办。
- 关键贡献：对检索质量做评估，必要时纠正或补充检索。
- 怎么学习：看 corrective workflow。
- 面试价值：回答 RAG 失败修复。
- 落地注意：需要检索评估器和二次检索策略。

## 35 RAPTOR

- 核心问题：长文档多层级信息如何检索。
- 关键贡献：递归摘要形成树状索引。
- 怎么学习：理解层级摘要和树检索。
- 面试价值：回答长文档 RAG。
- 落地注意：摘要错误会向上传播。

## 36 GraphRAG

- 核心问题：局部 chunk 检索难以回答全局关系问题。
- 关键贡献：抽取实体关系图，用社区摘要支持全局问答。
- 怎么学习：重点看 local/global query。
- 面试价值：企业知识库系统设计高频。
- 落地注意：图构建成本高，更新和纠错复杂。

## 37 Synergizing RAG and Reasoning

- 核心问题：RAG 与推理如何互相增强。
- 关键贡献：系统梳理 reasoning-enhanced RAG 和 RAG-enhanced reasoning。
- 怎么学习：作为 Agentic RAG 地图。
- 面试价值：回答复杂知识推理系统设计。
- 落地注意：多步检索需要中间监督和成本控制。

## 38 Reasoning Agentic RAG

- 核心问题：工业场景中 RAG 如何从静态管道变成智能体。
- 关键贡献：区分 predefined reasoning 和 agentic reasoning。
- 怎么学习：对照普通 RAG、Self-RAG、CRAG。
- 面试价值：解释 Agentic RAG。
- 落地注意：Agentic RAG 更强但更难评估。

## 39 MRKL

- 核心问题：如何让神经模型和符号工具协同。
- 关键贡献：模块化专家路由。
- 怎么学习：理解 router + expert。
- 面试价值：Tool use 的早期思想。
- 落地注意：现代工具调用 Agent 仍需要路由和工具选择。

## 40 Toolformer

- 核心问题：模型如何学会何时调用工具。
- 关键贡献：自监督构造 API 调用训练数据。
- 怎么学习：看样本筛选逻辑。
- 面试价值：工具使用训练范式。
- 落地注意：工程上常用 prompt/function calling，训练成本较高。

## 41 HuggingGPT

- 核心问题：LLM 如何调度多个 AI 模型完成复杂任务。
- 关键贡献：ChatGPT 作为控制器，调用 Hugging Face 模型。
- 怎么学习：看 task planning、model selection、execution、response generation。
- 面试价值：模型即工具的例子。
- 落地注意：工具描述质量影响选择准确性。

## 42 API-Bank

- 核心问题：如何评估 LLM API 调用能力。
- 关键贡献：提供 API 调用任务和评估设置。
- 怎么学习：关注参数生成、调用顺序、结果使用。
- 面试价值：工具调用评估。
- 落地注意：真实 API 需要权限和异常处理。

## 43 Gorilla

- 核心问题：LLM 如何连接大量 API。
- 关键贡献：面向 API 调用的模型和数据。
- 怎么学习：看 API retrieval 和函数调用。
- 面试价值：回答大规模工具库如何选工具。
- 落地注意：工具库越大，检索和 schema 管理越重要。

## 44 ToolLLM / ToolBench

- 核心问题：如何让模型掌握大量真实世界 API。
- 关键贡献：ToolBench 数据集、ToolLLM、工具调用评估。
- 怎么学习：重点看工具检索、规划、调用链。
- 面试价值：工具调用 Agent 必读。
- 落地注意：多 API 组合需要轨迹评估。

## 45 ToolEmu

- 核心问题：工具调用 Agent 的风险如何识别。
- 关键贡献：用模拟器测试危险工具行为。
- 怎么学习：关注风险分类和 adversarial 场景。
- 面试价值：Agent 安全高频。
- 落地注意：生产必须有权限、审计、确认机制。

## 46 CodeAct

- 核心问题：JSON/文本 action 表达能力不足怎么办。
- 关键贡献：用可执行代码作为 Agent 行动空间。
- 怎么学习：理解代码 action、解释器反馈、自调试。
- 面试价值：软件 Agent 和数据 Agent 高频。
- 落地注意：必须沙箱、限制库、超时、审计。

## 47 ReAct

- 核心问题：如何把推理和环境行动结合。
- 关键贡献：Thought/Action/Observation 循环。
- 怎么学习：手写一个最小 ReAct Agent。
- 面试价值：Agent 基础必问。
- 落地注意：加最大步数、工具白名单、参数校验、trace。

## 48 Reflexion

- 核心问题：Agent 如何从失败中学习但不更新参数。
- 关键贡献：把失败经验写成语言反思并存入记忆。
- 怎么学习：跑重复任务，对比有无 reflection。
- 面试价值：解释反思机制收益和局限。
- 落地注意：错误反思会污染上下文。

## 49 Generative Agents

- 核心问题：如何模拟长期一致的人类行为。
- 关键贡献：memory stream、reflection、planning。
- 怎么学习：重点看记忆评分：recency、relevance、importance。
- 面试价值：长期记忆 Agent 设计。
- 落地注意：模拟行为不等于生产可靠性。

## 50 Voyager

- 核心问题：开放环境中 Agent 如何持续学习。
- 关键贡献：自动课程、技能库、迭代代码生成。
- 怎么学习：关注 skill library。
- 面试价值：解释 Agent 技能积累。
- 落地注意：技能复用需要检索、验证和清理。

## 51 AgentBench

- 核心问题：如何统一评估 LLM 作为 Agent 的能力。
- 关键贡献：多环境 Agent benchmark。
- 怎么学习：看任务类型和评估维度。
- 面试价值：Agent 评估必读。
- 落地注意：benchmark 成绩不等于生产稳定性。

## 52 WebArena

- 核心问题：Web Agent 如何在真实网页环境中执行任务。
- 关键贡献：真实网站环境和任务集。
- 怎么学习：理解网页操作、观察、动作空间。
- 面试价值：Computer Use/Web Agent。
- 落地注意：网页动态变化和安全风险高。

## 53 LATS

- 核心问题：单路径 Agent 容易走错怎么办。
- 关键贡献：把 tree search 引入语言 Agent。
- 怎么学习：看候选动作生成、评估、回溯。
- 面试价值：规划与搜索 Agent。
- 落地注意：成本高，需预算控制。

## 54 AutoGen

- 核心问题：如何工程化构建多 Agent 应用。
- 关键贡献：Conversable Agent、多角色协作、工具执行。
- 怎么学习：实现 Planner/Executor/Reviewer。
- 面试价值：多 Agent 框架。
- 落地注意：终止条件和成本控制非常关键。

## 55 Agentic Reasoning

- 核心问题：如何系统理解 LLM 从生成器到行动者。
- 关键贡献：基础、进化、协作三层路线图。
- 怎么学习：作为 Agentic AI 总地图。
- 面试价值：回答 Agent 领域全局趋势。
- 落地注意：把论文框架映射到自己的项目能力矩阵。

## 56 Agentic AI Architectures

- 核心问题：Agentic AI 架构、分类和评估如何组织。
- 关键贡献：模块化拆解 perception、memory、planning、action、tool、collaboration。
- 怎么学习：用它检查自己的系统设计。
- 面试价值：生产级 Agent 架构设计。
- 落地注意：分类不能替代实现，仍需指标和安全。

## 57 MemGPT

- 核心问题：上下文窗口有限时如何管理长期状态。
- 关键贡献：把 LLM 类比操作系统，管理虚拟上下文和外部记忆。
- 怎么学习：理解 core memory、archival memory。
- 面试价值：长期记忆基础。
- 落地注意：记忆分页和检索需要清晰策略。

## 58 LoCoMo

- 核心问题：长期对话记忆如何评估。
- 关键贡献：多轮长对话记忆 benchmark。
- 怎么学习：关注单跳、多跳、时间、偏好问题。
- 面试价值：记忆评估。
- 落地注意：测试集要覆盖事实更新和时间推理。

## 59 A-MEM

- 核心问题：记忆如何成为 Agent 主动能力。
- 关键贡献：围绕记忆构建、管理、检索的 Agentic Memory。
- 怎么学习：和 MemGPT/Mem0 对照。
- 面试价值：长期 Agent 高频。
- 落地注意：记忆污染、权限、删除机制必须设计。

## 60 Mem0

- 核心问题：生产 Agent 如何低成本维护长期记忆。
- 关键贡献：动态抽取、整合、检索，兼顾准确率、延迟和 token 成本。
- 怎么学习：重点看 memory extraction、graph memory、LOCOMO 实验。
- 面试价值：生产记忆系统设计。
- 落地注意：不能把所有历史塞进 prompt。

## 61 MemoryAgentBench

- 核心问题：记忆 Agent 是否具备检索、学习、长程理解、选择性遗忘。
- 关键贡献：增量多轮交互评估。
- 怎么学习：理解四类能力。
- 面试价值：记忆评估升级。
- 落地注意：长期记忆系统必须测遗忘和冲突更新。

## 62 CAMEL

- 核心问题：多 Agent 角色扮演是否能产生协作行为。
- 关键贡献：通过角色设定和对话推动任务完成。
- 怎么学习：看 role-playing prompt。
- 面试价值：多 Agent 起点。
- 落地注意：角色扮演容易发散，需任务约束。

## 63 ChatDev

- 核心问题：能否用多 Agent 模拟软件公司开发流程。
- 关键贡献：CEO/CTO/Programmer/Reviewer 等角色协作。
- 怎么学习：看软件开发流水线。
- 面试价值：多 Agent 软件开发案例。
- 落地注意：真实工程需要测试、代码审查和权限控制。

## 64 MetaGPT

- 核心问题：多 Agent 如何通过 SOP 协同。
- 关键贡献：把标准作业流程引入多 Agent。
- 怎么学习：重点理解 SOP、角色产物和依赖。
- 面试价值：多 Agent 系统设计高频。
- 落地注意：流程清晰比“多模型聊天”更重要。

## 65 AgentVerse

- 核心问题：如何构建和研究多 Agent 协作与涌现行为。
- 关键贡献：多 Agent 框架和任务环境。
- 怎么学习：关注协作、通信、环境反馈。
- 面试价值：补充多 Agent 框架视角。
- 落地注意：涌现行为难控，评估要严格。

## 66 Mixture-of-Agents

- 核心问题：多个模型/Agent 的回答能否相互增强。
- 关键贡献：proposer + aggregator，多模型协作提升质量。
- 怎么学习：看分层聚合和模型多样性。
- 面试价值：解释 MoA 与 MoE、多 Agent 的区别。
- 落地注意：质量提升伴随成本和延迟上升。

## 补充专题：评估、安全和软件工程 Agent

### HELM

- 学习重点：多维度评估，不只看准确率。
- 面试价值：说明 LLM 评估应覆盖准确性、鲁棒性、公平性、效率。

### BIG-bench

- 学习重点：大规模任务集合如何暴露模型能力边界。
- 面试价值：解释 benchmark 的意义和局限。

### MMLU

- 学习重点：多任务知识评估。
- 面试价值：说明模型榜单常用指标，但不能代表 Agent 能力。

### SWE-bench

- 学习重点：真实 GitHub issue 修复任务。
- 面试价值：软件工程 Agent 的标准评估。

### SWE-agent

- 学习重点：Agent-Computer Interface。
- 面试价值：解释为什么接口设计会影响 Agent 能力上限。

### Agent Evaluation Surveys

- 学习重点：结果、过程、成本、安全、鲁棒性。
- 面试价值：回答生产级 Agent 如何评估。
