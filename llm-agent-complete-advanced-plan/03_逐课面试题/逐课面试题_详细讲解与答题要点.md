# 逐课面试题：详细讲解与答题要点

> 本文件用于面试前集中复习。每组题对应课程主题，先给详细解释，再给答题要点。建议每天选 3 道题录音复述。

## 1. Transformer 与 LLM 基础

### 题 1：Transformer 为什么成为大模型主流架构？

详细讲解：

Transformer 的核心优势是 Self-Attention。它能让每个 token 直接关注序列中其他 token，从而建模长距离依赖；同时它不像 RNN 那样必须顺序处理 token，因此可以在大规模硬件上并行训练。随着数据、参数和计算量扩大，Transformer 表现出很好的 scaling 特性，所以成为 GPT、LLaMA、Mistral 等模型的主流基础架构。

答题要点：

- Self-Attention 建模 token 关系；
- 并行训练；
- 可扩展；
- 适合 next token prediction；
- 缺点是长上下文成本高。

### 题 2：BERT、GPT、T5 的区别？

详细讲解：

BERT 是 Encoder-only，适合理解任务；GPT 是 Decoder-only，适合自回归生成；T5 是 Encoder-Decoder，把所有任务统一成 text-to-text。面试中不要只说名字，要从架构、训练目标和适用任务三方面比较。

答题要点：

- BERT：MLM，理解；
- GPT：causal LM，生成；
- T5：text-to-text，编码-解码；
- 现代 LLM Agent 多基于 GPT/LLaMA 类 Decoder-only 模型。

## 2. 后训练与对齐

### 题 3：SFT、RLHF、DPO 分别解决什么？

详细讲解：

SFT 让模型学会按照指令格式回答；RLHF 用人类偏好训练 reward model，再优化模型行为；DPO 直接使用偏好对进行优化，省去显式 reward model。Agent 场景中，SFT 可训练工具调用格式，偏好优化可提升有用性和安全性，但不能替代系统层工具权限和评估。

答题要点：

- SFT：监督指令学习；
- RLHF：reward model + RL；
- DPO：直接偏好优化；
- Agent 仍需工程约束。

### 题 4：推理模型为什么会更慢？

详细讲解：

推理模型会在回答前生成更长的中间思考或搜索更多候选路径，本质是用更多 test-time compute 换准确率。复杂任务中这很有价值，但简单任务会造成过度思考和成本浪费。

答题要点：

- 长 CoT；
- test-time scaling；
- 准确率与成本权衡；
- 需要模型路由。

## 3. RAG 与上下文工程

### 题 5：完整 RAG 系统有哪些模块？

详细讲解：

完整 RAG 不只是“向量库 + Prompt”。它包含文档解析、清洗、切分、embedding、索引、召回、重排、上下文构造、答案生成、引用、评估、权限和更新机制。任何一层失败都会影响最终答案。

答题要点：

- loader/parser/splitter；
- embedding/index；
- retriever/reranker；
- generator/citation；
- evaluation/permission。

### 题 6：RAG 答错怎么排查？

详细讲解：

先看检索是否命中正确证据。如果没有命中，查解析、切分、embedding、query rewrite、top-k；如果命中了但答案错，查 rerank、上下文顺序、prompt、模型忠实度和引用策略。不要一开始就调 prompt。

答题要点：

- 先检索，后生成；
- 分层排查；
- 建 gold evidence；
- 记录失败类型。

### 题 7：GraphRAG 解决什么问题？

详细讲解：

普通 chunk RAG 适合局部事实问答，但对跨文档关系、全局总结和实体社区问题不稳定。GraphRAG 抽取实体与关系，形成图和社区摘要，适合组织级知识分析。

答题要点：

- 实体关系；
- 全局问题；
- 社区摘要；
- 成本和更新复杂。

## 4. Tool Use 与 Agent Loop

### 题 8：Agent 和 Chatbot 的本质区别？

详细讲解：

Chatbot 主要生成文本回复，Agent 围绕目标维护状态、调用工具、接收环境反馈，并通过多步循环完成任务。Agent 的难点不只是模型回答，而是状态、工具、安全、评估和失败恢复。

答题要点：

- 目标；
- 状态；
- 工具；
- observation；
- 多步执行。

### 题 9：ReAct 的核心是什么？

详细讲解：

ReAct 把 reasoning 和 acting 交替组织：Thought 决定下一步，Action 调用工具，Observation 返回环境结果，模型再继续推理。这让模型能通过外部反馈修正自身，而不是只在内部猜测。

答题要点：

- Thought/Action/Observation；
- 外部反馈；
- 降低幻觉；
- 需要最大步数和工具校验。

### 题 10：工具调用如何保证安全？

详细讲解：

工具调用必须有白名单、schema、参数校验、权限控制、超时、重试、审计和高风险人工确认。外部网页、文件和工具结果只能作为数据，不能覆盖系统指令。

答题要点：

- whitelist；
- schema validation；
- least privilege；
- audit；
- human confirmation。

## 5. Memory 与长期任务

### 题 11：长期记忆和长上下文有什么区别？

详细讲解：

长上下文是一次推理能放更多 token；长期记忆是跨会话保存、检索、更新和删除信息的系统。长上下文不能解决用户偏好变化、隐私删除、记忆冲突和长期个性化问题。

答题要点：

- context window 是临时容量；
- memory 是持久系统；
- 要支持更新和删除；
- 记忆需要评估。

### 题 12：如何设计记忆系统？

详细讲解：

先定义记忆类型，如偏好、事实、任务、技能、约束；再设计抽取、存储、检索、更新、遗忘、删除和审计。每条记忆要有来源、时间、置信度和用户归属。

答题要点：

- memory schema；
- extraction；
- retrieval；
- conflict update；
- privacy delete。

### 题 13：记忆污染如何处理？

详细讲解：

记忆污染来自错误信息、过期信息、恶意内容或跨用户泄露。应通过写入过滤、用户确认、来源记录、冲突检测、过期机制、删除机制和权限隔离治理。

答题要点：

- high confidence write；
- source tracking；
- conflict detection；
- expiration；
- user control。

## 6. Multi-Agent 与 CodeAct

### 题 14：多 Agent 一定更强吗？

详细讲解：

不一定。多 Agent 能带来角色分工、并行探索和审查机制，但也带来成本、延迟、无效争论和错误传播。关键是协议、角色、终止条件和评估，而不是 Agent 数量。

答题要点：

- role specialization；
- coordination cost；
- protocol；
- termination；
- metrics。

### 题 15：CodeAct 为什么重要？

详细讲解：

CodeAct 把可执行代码作为行动空间，使 Agent 能表达变量、条件、循环和多工具组合。解释器提供确定性反馈，帮助自调试。它特别适合软件工程和数据分析任务。

答题要点：

- code as action；
- control flow；
- interpreter feedback；
- sandbox required。

### 题 16：MetaGPT 的 SOP 思想有什么价值？

详细讲解：

MetaGPT 把标准作业流程引入多 Agent，让角色产物、依赖和协作步骤明确化。相比自由聊天，SOP 更稳定、更容易评估和复盘。

答题要点：

- SOP；
- role artifacts；
- structured collaboration；
- lower chaos。

## 7. Evaluation 与 Safety

### 题 17：Agent 怎么评估？

详细讲解：

Agent 评估要覆盖结果和过程。结果看任务成功率、答案质量；过程看步数、工具调用、无效操作、成本、延迟；安全看越权、注入、隐私泄露。还要有 trace，方便定位失败发生在哪一步。

答题要点：

- success rate；
- trajectory；
- tool calls；
- cost/latency；
- safety。

### 题 18：为什么 LLM-as-Judge 不够？

详细讲解：

LLM 裁判方便但有偏差，可能偏好长答案、受提示影响或无法验证事实。生产评估需要规则指标、gold answer、人工抽检和真实用户反馈结合。

答题要点：

- judge bias；
- gold data；
- human audit；
- rule metrics。

### 题 19：Prompt Injection 如何防？

详细讲解：

核心是区分指令和数据。系统指令、开发者指令、用户指令、外部内容有不同优先级，外部内容不能覆盖系统规则。工具调用还要做权限隔离和参数校验。

答题要点：

- instruction hierarchy；
- external data isolation；
- permission；
- audit；
- confirmation。

## 8. Software Agent 与系统设计

### 题 20：SWE-agent 的关键启发是什么？

详细讲解：

软件 Agent 能力不只取决于模型，还取决于 Agent-Computer Interface。给 Agent 合适的搜索、查看、编辑和测试命令，比直接让它猜代码更可靠。

答题要点：

- ACI；
- search/read/edit/test；
- feedback loop；
- minimal patch。

### 题 21：设计一个企业知识库 Agent

详细讲解：

应从数据接入、权限过滤、解析切分、混合检索、重排、生成引用、拒答、评估和安全审计完整设计。重点说明如何防止权限泄露和引用幻觉。

答题要点：

- document pipeline；
- ACL before retrieval；
- hybrid search；
- citation；
- eval。

### 题 22：设计一个生产级 Agent 平台

详细讲解：

平台应包含模型路由、状态管理、工具注册、权限控制、执行引擎、记忆系统、RAG、trace、评估、成本监控和安全策略。设计时要强调模块边界和可观测性。

答题要点：

- model router；
- state engine；
- tool registry；
- memory/RAG；
- observability；
- safety。

## 9. 项目复盘题

### 题 23：介绍你最复杂的 Agent 项目

详细讲解：

回答不要只说技术栈。要先讲业务目标，再讲架构，再讲难点、失败案例、评估指标和优化结果。面试官更看重你是否真的做过系统排查。

答题要点：

- background；
- architecture；
- challenge；
- metrics；
- failure and fix。

### 题 24：项目中最难的问题是什么？

详细讲解：

优秀回答通常是具体问题，如检索召回差、工具误调用、记忆冲突、成本高、延迟高、安全注入。要讲你如何定位、如何修改、指标如何变化。

答题要点：

- concrete issue；
- diagnosis；
- solution；
- before/after metrics。

### 题 25：如果重新做，你会怎么改？

详细讲解：

体现复盘能力。可以从评估前置、工具权限、trace、测试集、模块化、成本控制、用户反馈闭环等方面回答。

答题要点：

- eval first；
- trace first；
- stricter permissions；
- better datasets；
- iterative improvement。

## 每天练习方法

1. 任选 3 道题；
2. 每道题先 30 秒回答；
3. 再按详细讲解扩展到 2 分钟；
4. 录音回听，检查是否包含“定义、机制、工程、评估、风险”。
